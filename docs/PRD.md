## 1. 제품 정의

- **PMS**: 여러 고객사 프로젝트를 인력(M/M)·가동률·유지보수 이력 관점에서 관리하는 사내 도구. 스프레드시트를 대체한다. — 상세: `PRD-pms.md`
- **AI 어시스턴트**: PMS 데이터를 자연어로 조회하고 본인 진척률을 수정하는 사내 챗봇. 표현 다양성을 의도로 접는 일은 LLM이, 계산·권한·데이터 접근은 PMS 로직(결정론)이 담당한다. — 상세: `PRD-host.md`
- **관계**: AI 호스트 Boot 앱(에이전트 루프·LLM·MCP 클라이언트) ↔ PMS Boot 앱 내 임베디드 `/mcp` 어댑터. 구조 원칙 7개는 루트 `CLAUDE.md`가 원본.

## 3. 용어 정의 (공통)

| 용어 | 정의 |
|------|------|
| M/M | Man-Month. 배정 강도 단위 (예: 0.5MM = 월 절반 투입) |
| 가동률(기본) | 당월 배정 M/M 합 ÷ 가용 M/M(capacity) × 100 (%) |
| 보정 가동률 | 기본 가동률을 직급계수(gradeCoeff)로 보정 — Σ배정MM ÷ (가용MM × coeff) × 100. 예: 책임(coeff 1.2), 배정 0.5+0.7, 가용 1.0 → 기본 120% / 보정 100% (PRD-pms AC C1-2와 동일 수치. 직급계수 값은 시드 — §5) |
| 오버부킹(과부하) | 보정 가동률 100% 초과 상태 |
| version | 수정 가능 엔티티의 낙관적 락 버전 번호. 쓰기 시 필수, 불일치는 409 → 재확인 절차 |

## 4. 권한 모델

두 축을 **절대 하나로 합치지 않는다**. 행위 허용 = 가시성 통과 AND 권한 허용. 서버가 최종 판정하고, 프론트·챗은 노출 제어만 한다. **챗에서 보이는 것 = 화면에서 보이는 것.**

| 축 | 값 | 결정 | 소유 모듈 |
|----|----|------|-----------|
| 조직 가시성 | ADMIN(대표)=전사 / 부문장(DIVISION_HEAD)=자기 부문 / 팀장(TEAM_LEAD)=자기 팀 / 팀원(MEMBER)=본인 참여 — 시드 `people.json` orgRole과 정합 | 무엇이 보이나 | identity |
| 프로젝트 권한 | 관리자 / 담당자 | 무엇을 할 수 있나 | project |

| 기능 | 관리자 | 담당자 |
|------|--------|--------|
| 범위 내 프로젝트 조회 | O | 본인/팀 |
| 프로젝트 등록/수정/삭제 | O | ✕ |
| 인력 배정 / M/M 입력 | O | ✕ |
| 진척률 수정 | O | 본인 참여만 |
| 유지보수 이관/이력 | O | ✕ |

- **가시성 밖 = 404 은닉**: 서버는 권한 밖과 부재를 구분해 주지 않는다(구조 원칙 3). 목록은 가시성 내 부분집합만, 단건은 404 — 화면·API·챗 응답 모두 동일 의미론.
- ADMIN=전사 가시성은 시드 orgRole(대표이사 1명)을 근거로 2026-08-02 추가 — **게이트 P에서 최종 승인**.
- **재기술 검토 중(2026-08-02)**: `frontend/` 프로토타입은 orgRole별 기능 플래그(viewAll·createProj·manageProj·editProgress·manageOrg) + 프로젝트 관리자(managerId) + 배정 조합으로 동작하며, 부문장 진척률 수정 불가·가동률 집계에서 대표 직속(프로텐) 제외 규칙을 포함 — 이 방식으로 본 절을 재기술할지는 pms 담당 결정 대기(PRD-pms 12장 · PROGRESS 미해결 이슈).

## 6. 협업 접점 (2인 계약 경계)

MCP 도구 카탈로그(`PRD-host.md` §4-2) ↔ PMS 애플리케이션 서비스(`PRD-pms.md` EPIC A·C·D)의 대응이 두 트랙의 계약이다. 어느 쪽이든 접점 변경은 `docs/PROGRESS.md` 결정 기록 경유 + 양측 합의 — 도구명·설명·시스템 프롬프트·Eval 셋은 한 세트로 관리한다(하나를 바꾸면 넷을 같이 바꾼다).
