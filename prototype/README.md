# PMS 화면 프로토타입 (기획 검증용)

PRD-pms v2.4 부록 A의 화면 명세를 **백엔드 없이** 눈으로 검증하기 위한 목업 앱.
"우리가 기획한 기능이 맞는가"를 게이트 P 전후로 확인하는 리뷰 보조 도구다.

- **명세가 아니다** — 충돌 시 `docs/PRD-pms.md`·`docs/PRD.md`가 원본.
- 기존 `frontend/`(구 백엔드 실연동본)는 참고용으로 보존 — 이 앱은 v2.4 최신
  기획(phase 탭·유지보수 3층·완료/재개·권한 커스텀)을 반영한 재구성본.
  M1 재연동 시 어느 쪽을 기반으로 할지 그때 결정.
- 데이터: `reference/seed/`의 44명·382프로젝트를 그대로 적재. 시드에 없는
  값(월별 M/M·billable 팀 목록·유지보수 계약)은 화면 검증용 가정으로 채웠고,
  각 파일 주석에 가정임을 명시했다. 새로고침 시 초기화(in-memory).

## 실행

```bash
cd prototype
npm install
npm run dev   # http://localhost:5174
```

로그인: 시드 이메일 + `proten1!` (또는 로그인 화면의 데모 계정 버튼).
헤더의 **사용자 전환** 셀렉트로 44명 아무나로 바꿔가며 권한·가시성을 검증한다.

## 검증 포인트 (기획 리뷰 시 볼 것)

| 화면 | 재현한 규칙 |
|------|-------------|
| 프로젝트 목록 | phase 탭 = status 파생(영업/솔루션) · 완료 건 "이관 대기" 뱃지 · 유지보수중은 계약 탭으로 |
| 프로젝트 상세 | 진척률 2단계 확인(요약→확정) · 100%여도 자동 완료 없음(completable 안내) · 완료 상태 수정 409 · 재개 시 90% 리셋 · 유지보수중 재개 불가 |
| 권한 탭 | 역할×기능 토글(US-A8) — PM 열·조회·삭제/이관 잠금, 완료·재개 한 토글, 커스텀 뱃지, 기본값 복원 |
| 이력 탭 | AuditLog 단일 원본의 projectId 필터 뷰(참여자도 조회) |
| 가시성 | orgRole별 목록 차이 + 배정 합집합, 범위 밖 상세 = 404 은닉 문구 |
| 가동률 | 기본/보정 산식 · billable 모집단(집계 포함/제외 컬럼) · 과부하 강조 |
| 유지보수 | 계약(1:N 사이트, 담당 엔지니어 정본) · 직접 등록/이관 입구 2개 · 이슈 기본 배정=사이트 엔지니어 · append-only 코멘트 · 미배정/내 담당 필터 |
| 이관 모달 | 계약 필수값 + 사이트·엔지니어 없이는 이관 불가(D1-3) |
| 설정(ADMIN) | 사용자 CRUD·통합 감사로그 · 비ADMIN 접근 시 403 안내 |

권한 없는 버튼은 렌더링하지 않되, 스토어(가짜 서버)의 403/404/409/422 검증은
항상 존재한다 — 부록 A 공통 UI 규칙의 재현.
