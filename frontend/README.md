# frontend/ — PMS 웹 클라이언트 (백엔드 실연동)

`pms/` 앱의 구현된 API에만 붙는 React + TypeScript 클라이언트다.
디자인(팔레트·레이아웃·컴포넌트 클래스)은 이전 프로토타입의 `styles.css`를 그대로
쓰고, 데이터·상태·API 계층은 현재 백엔드 계약(PRD-pms §7)에 맞춰 새로 썼다
(2026-08-22).

> 기획 검증용 목업 앱은 `prototype/`이다(백엔드 없음, PRD v2.4 화면 전체).
> 이 앱은 그 반대다 — **실제로 동작하는 것만** 있다.

## 실행

```bash
docker compose -f ../pms/docker-compose.yml up -d   # PostgreSQL
(cd ../pms && ./gradlew bootRun)                    # 백엔드 :8080
npm install && npm run dev                          # 이 앱 :5173
(cd ../host && ./gradlew bootRun)                   # AI 어시스턴트를 쓸 때만 :8081
```

`vite.config.ts`가 `/api` 요청을 `localhost:8080`으로 프록시하므로 CORS 설정이 없다.

로그인: 시드 계정 이메일 + `proten1!` (로그인 화면의 시드 계정 4행 = 권한 그룹별 화자
— 관리자·부문장·팀장·팀원).

## 로그인을 건너뛰고 쓰기 (개발 모드)

인증이 꺼진 기본 설정에서는 서버가 `X-Caller-Person-Id` 헤더만 보므로 **로그인 없이
화자만 지정해** 나머지 기능을 볼 수 있다.

- 로그인 화면 시드 계정 행의 **`바로 시작`** 버튼 → 그 사람으로 즉시 진입
- 또는 아래 **`로그인 없이 둘러보기`** 카드에 personId(시드 1~43)를 넣고 시작
- 진입 후에는 상단 바의 **화자 셀렉트**로 로그아웃 없이 사람을 바꿀 수 있다.
  목록은 *지금까지 본 인원의 누적 명부*라 가시성이 좁은 화자로 옮겨도 되돌아올 수
  있고, 명부에 없는 사람은 옆의 `id` 칸에 personId를 직접 넣는다.

이 모드는 헤더를 신뢰하므로 **개발용이다.** 인증을 켜면 서버가 401로 막고 화면은
"인증이 켜져 있어 화자 지정으로는 들어갈 수 없습니다"라며 로그인으로 되돌린다.
없는 personId를 넣으면 404를 받아 같은 방식으로 되돌린다.

## 인증 두 모드를 모두 지원한다

백엔드 스위치 `pms.auth.enabled`가 어느 쪽이든 같은 화면이 동작한다.

| 스위치 | 서버가 보는 화자 | 이 앱이 보내는 것 |
|--------|------------------|-------------------|
| `false` (기본) | `X-Caller-Person-Id` 헤더 | 로그인 세션: 토큰 + 헤더 / 화자 지정 세션: 헤더만 |
| `true` | access 토큰의 `sub` | 같음 — 헤더는 서버가 무시하고, 화자 지정 세션은 401이다 |

로그인·갱신 라우트는 두 모드에서 모두 열려 있어서, 어느 쪽이든 로그인해서 받은
토큰의 `sub`를 헤더로도 실으면 배선이 하나로 끝난다(`src/api.ts`).
**인증 OFF는 헤더를 신뢰하는 개발 모드다 — 그대로 외부에 노출하면 안 된다.**

인증을 켜고 확인하려면:

```bash
(cd ../pms && ./gradlew bootRun --args='--pms.auth.enabled=true')
```

## AI 어시스턴트 — 지금은 임시 배선이다 (2026-08-27)

화면은 정본 경로 `POST /api/chat`을 부른다. 그런데 그 자리에 설 **pms chat BFF는 아직
없고**(PRD-pms §7 — 상세 계약 M1 확정), `vite.config.ts`가 그 경로만 host 앱(8081)의 대역
엔드포인트로 돌린다. BFF가 서면 **프록시 항목 하나를 지우는 것으로 끝난다** — 화면도
`api.ts`도 바뀌지 않는다.

**임시 동안 없는 것**(셋 다 BFF의 몫 — `docs/구현_노트.md` §1-2):

| 없는 것 | 정본에서는 | 지금은 |
|---------|-----------|--------|
| 입력 길이 차단 (FR-AI-02) | BFF가 2,000자에서 자른다 | 그대로 모델까지 간다 |
| 레이트리밋 (FR-AI-06) | 일 50질의 소프트 리밋 | 없다 |
| 위임 토큰 | 만료 5분 · `channel=ai-assistant` 감사 표식 | 로그인 세션 토큰이 그대로 host로 간다 |

그래서 **이 배선은 로컬 개발 전용이며 그대로 노출하면 안 된다** — 인증 OFF 모드와 같은
조건이다. 피드백 버튼(FR-AI-05)도 저장할 `POST /api/chat/feedback`이 없어 두지 않았다.

**챗은 로그인 세션에서만 된다.** 대역이 Bearer 토큰의 `sub`로 화자를 읽으므로 `바로 시작`
(화자 지정) 세션에는 실을 것이 없고, 화면이 입력창 대신 그 사실을 적는다. 이것은 임시의
결함이 아니라 정본과 같은 성질이다 — BFF도 `Authentication`을 요구한다.

**쓰기 2단계 확인(원칙 5)에 화면 부품이 없다.** 확인 카드도 확정 버튼도 없이, 요약을 받고
"확정"이라고 답하는 **대화 그대로** 진행된다. 무엇을 요약하고 무엇을 거절할지는 에이전트와
서버의 판정이라 화면이 카드를 그리면 같은 규칙이 두 곳에 생긴다(`prototype/`의 목업
ChatPanel이 카드를 그렸던 것은 뒤에 백엔드가 없어서였다).

대화 기억은 서버가 든다 — host가 `sub:conversationId`로 최근 10턴을 보관한다. 그래서
화면의 **'새 대화'는 말풍선만 지우는 것이 아니라 id를 갈아 끼운다**(`src/chat.ts`):
말풍선만 지우면 화면은 비었는데 서버는 앞 대화를 기억하는 상태가 된다.

**답변은 마크다운으로 그린다** — react-markdown + remark-gfm(이 앱의 유일한 런타임 의존
2개다). 프롬프트가 표를 허용하고 있어서(`SystemPrompts` "[톤과 형식]") 굵게·목록에 더해
**GFM 표가 실제로 온다** — 직접 짠 파서로는 파이프가 그대로 보인다.

렌더 범위는 좁혀 두었다. 답변에는 프로젝트 설명·이력 비고 같은 **DB 텍스트가 섞여 들어오고
그것은 데이터일 뿐이기 때문이다(원칙 6)**:

- `skipHtml` — 원시 HTML은 버린다(rehype-raw를 안 붙였으니 실행될 일은 애초에 없고, 글자로
  새어 나오는 것까지 막는다)
- **`img` 금지** — 클릭 없이 외부 요청을 내는 유일한 태그다. 남의 DB 문자열이 우리 화면에서
  추적 픽셀이 되는 경로를 닫는다
- 링크는 새 탭 + `noreferrer`(`javascript:` 류는 react-markdown 기본 `urlTransform`이 막는다)
- **내가 친 말과 오류 문구는 마크다운으로 해석하지 않는다** — 글자 그대로 둔다

표가 400px 패널보다 넓어지면 **말풍선이 아니라 표가** 가로로 스크롤된다(`styles.css`).

"전 프로젝트 관리" 플래그 보유자(기본: 관리자)는 모든 프로젝트에서 PM으로 간주된다

**감사 표는 두 화면이 공유한다**(`components/AuditTable.tsx`): 통합 로그와 프로젝트
이력이 **같은 행**을 다른 필터로 보여 주므로(별도 저장 없음 — G1-1·G1-2), 표를 두 벌

105계약을 홈에서 미리 받을 이유가 없다.

## 배포 요구 — SSE 토큰 마스킹 (F1-4, 2026-08-25)

`GET /api/notifications/stream`은 **쿼리 파라미터로 인증한다**(`?access_token=`).
EventSource가 커스텀 헤더를 싣지 못해서이고, PRD-pms §7이 그렇게 정했다.

그래서 **역방향 프록시의 액세스 로그 포맷에서 `access_token`을 마스킹해야 한다**
(구현 노트 §6). 앱은 그 값을 스스로 로그에 남기지 않는 것까지만 책임진다 — 예외
문구에도 토큰이 들어가지 않는다. 마스킹 없이 그대로 두면 **유효한 access 토큰이
로그 파일에 평문으로 쌓인다.**

같은 location에 `proxy_buffering off`도 필요하다 — 버퍼링되면 "즉시 푸시"가 죽는다.
앱이 `X-Accel-Buffering: no`를 함께 내보내므로 Nginx는 그것만으로도 대개 통과한다.
